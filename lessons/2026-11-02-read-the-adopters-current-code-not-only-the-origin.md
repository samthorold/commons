The Sweep's rule *read the Origin, don't trust the claim* points at the PR where the Lesson was written. When an Adopter keeps working on the same mechanism after writing a Lesson, its current code can be ahead of both the Lesson and its Origin. In one grill, a Lesson's candidate rule said "a transport or provider error is not a sample". The Adopter's harness, revised since, draws a finer line: a call that brings back no answer is not a sample, but an answer returned as an error (a refusal, a cut-off) is. Promoting from the Lesson and its Origin alone would have landed the coarser rule. Several other Lessons of the same batch were also already running practice there, so the grill became mostly a catch-up.

Candidate rule: before promoting a Lesson whose Origin is more than a few days old, read the Adopter's current implementation of the mechanism (its code or docs at `main`) beside the Origin, and promote the form that is running. This applies to grills on a Guide's Lessons too.
