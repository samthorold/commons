# Emergent systems Guide: the model never contains its phenomena

How to apply the Stance *the model never contains its phenomena*, from [the Emergent systems Guide](../emergent-systems.md#stance-the-model-never-contains-its-phenomena), which states the Stance.

## Why, in full

A phenomenon produced by its own mechanism agrees with its parameters by construction, so it can't falsify anything, and the model stops being an instrument for studying it. It also hides the rule that was actually wrong.

## How to apply

- A new mechanism is checked by asking which phenomenon's outcome it sets directly. One that sets it is the phenomenon built in, whatever it's called.
- A test scenario built so that its outcome is guaranteed checks the wiring, not emergence. Design the starting state and the trigger, and let the rules decide what follows; only that counts as a reading.
- Where the domain itself fixes a behaviour (a regulation, a game's rules), it is a rule of the substrate, not a phenomenon, and encoding it is right.
