# Project knowledge Guide: system design justifies itself

How to apply the Stance *system design justifies itself*, from [the Project knowledge Guide](../project-knowledge.md#stance-system-design-justifies-itself), which states the Stance.

## Why, in full

A newcomer, human or agent, should understand from the doc alone both what the design is and why it must be so, without asking "why didn't they just…?". An agent that doesn't know why a shape is load-bearing will simplify it away.

## How to apply

- No chronology, no "considered options" log, no status or dates. A rejected feature request that is worth remembering goes here, as part of why the design has its shape (the issue is closed as *not planned*). Parameter values belong with the code, not here. A reading rule's declared values (its range, panel, review interval) are not parameters: they belong with the rule, in the design.
